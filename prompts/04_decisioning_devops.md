# Участник 4 — Скоринг и решения, интеграции-моки, Docker и DevOps

Скопируй блок между линиями в свой Claude в начале каждой сессии.

---
Ты работаешь в команде из 4 человек над хакатонным проектом «Умный кредитный кабинет предпринимателя». Ты помогаешь **Участнику 4 (скоринг и решения, моки интеграций, Docker/DevOps)**. Сначала прочитай `CLAUDE.md` и всё из `docs/`, особенно `SCORING.md`, `STATE_MACHINE.md`, `MVP.md`.

**Моя зона:** `backend/app/scoring`, `backend/app/decision`, `backend/app/integrations`, `mocks/` (БКИ и ЕГРЮЛ/ФНС), `seed/`, `docker-compose.yml`, `Makefile`, `.env.example`, `.github/workflows`, Dockerfile'ы. Остальной backend (API, БД, воркер) принадлежит Участнику 2, frontend Участнику 3.

**Задачи по порядку:**
1. **Каркас запуска (первым делом, чтобы остальные не ждали).** `docker-compose.yml` с сервисами `db` (postgres:16.x, версия зафиксирована), `backend`, `worker`, `frontend`, `mock-bki`, `mock-egrul`; healthcheck'и и `depends_on: condition: service_healthy`; тома для БД и загрузок; сеть; единый `.env.example`; `Makefile` (`make up`, `make down`, `make reset`, `make test`, `make seed`). Заготовки Dockerfile'ов с зафиксированными базовыми образами и без `latest`. Цель: `docker compose up --build` поднимает всё с нуля без ручных шагов.
2. **Моки интеграций.** Два небольших FastAPI-сервиса в `mocks/`:
   - `mock-egrul`: `GET /companies/{inn}` отдаёт название, форму, дату регистрации, ОКВЭД, адрес, статус (`ACTIVE/LIQUIDATING/LIQUIDATED`), флаги ФНС («Прозрачный бизнес»: массовый адрес и т.п.).
   - `mock-bki`: `GET /reports/{inn}` отдаёт `score` (0–1000), действующие и закрытые просрочки, суммы обязательств.
   Данные берутся из `seed/companies.yaml` детерминированно по ИНН (7 тестовых компаний из `docs/SCORING.md`; неизвестный ИНН: правдоподобные данные на основе хеша). Переменные для имитации сбоев: `MOCK_BKI_FAIL_FIRST_N`, `MOCK_BKI_LATENCY_MS`. Контракты моков описать в `docs/api/mocks.md`.
3. **Клиенты интеграций.** `backend/app/integrations`: клиенты БКИ и ЕГРЮЛ с таймаутом, повторами (экспоненциальная пауза), понятными ошибками. Интерфейс согласовать с Участником 2 (он вызывает их из воркера).
4. **Скоринг.** `backend/app/scoring` по таблице из `SCORING.md`: чистая функция `score(inputs) -> ScoringResult` с разбором по факторам и списком стоп-факторов. Пороги читаются из `config.yaml` (не в коде). Справочник ОКВЭД-риска `okved_risk.yaml`. Тесты параметризованы по тестовым компаниям.
5. **Решения.** `backend/app/decision` по матрице из `SCORING.md`: чистая функция `decide(inputs, result, product) -> Decision` (исход, оффер, `reason_codes`), расчёт доступной суммы по аннуитету, округление, надбавки ставки по группам. Тесты на каждую ветку матрицы и граничные значения.
6. **Синтетические данные.** `seed/companies.yaml`, `seed/users.yaml` (учётки из `docs/MVP.md`), `seed/products.yaml`; скрипт загрузки идемпотентный (повторный запуск не плодит дубли); вызов при старте при `SEED_ON_START=true` и по `make seed`. Сверь итоговые исходы 7 компаний с таблицей в `SCORING.md`; расхождение сначала ищи в коде, потом в данных; документ меняй только через согласование с Участником 1.
7. **CI.** GitHub Actions: линт, тесты backend и frontend, сборка Docker-образов, проверка, что `docker compose up` поднимается и `/health/ready` отвечает. Кэш зависимостей.
8. **Фиксация версий и безопасность окружения.** Lock-файлы (backend и frontend), теги образов, непривилегированные пользователи в контейнерах, отсутствие секретов в репозитории (только `.env.example` с демо-значениями), `.dockerignore`, `.gitignore`.
9. **Публикация (желательно).** Бесплатный хостинг (например, VPS бесплатного уровня или платформа с free tier: подбери вариант, который не требует платной подписки), краткая инструкция в `docs/deploy.md`. Локальный запуск при этом остаётся основным.
10. **ИИ (только если основной сценарий уже стабилен).** За флагом `AI_ENABLED`: объяснение решения клиенту простыми словами и краткая сводка заявки для оператора с помощью модели с открытыми весами (малая модель через Ollama в отдельном профиле compose). Обязателен детерминированный fallback на шаблоны по `reason_codes`. Модель и лицензия записываются для `THIRD_PARTY_NOTICES.md`. Решение о кредите ИИ не принимает.

**Правила:** скоринг и решение остаются чистыми функциями без БД и сети; пороги и справочники в конфигурации; все версии образов и зависимостей зафиксированы; ничего платного; все сторонние компоненты передавай Участнику 1 для `THIRD_PARTY_NOTICES.md`.

Начни с задачи 1. Сначала покажи план из 5–7 пунктов и дай мне подтвердить.
